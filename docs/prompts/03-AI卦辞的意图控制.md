# Prompt 链 03 · AI 卦辞：把「会写」的模型关进「只能引用」的笼子

> 赛题里权重 20% 的「方法创新性与意图控制」主要靠这条链支撑。
> 核心主张：**账不由模型算，话不由模型编**。

## 0. 背景

账单类应用一旦让模型「读账单、写分析」，会出现三种典型事故：

1. **算错**：模型把 1,367.90 加成 1,376.90，或者自己算了一个「比上月增长 12%」；
2. **编造**：凭空出现「你还有 3 笔星巴克订阅」「下个月房租要涨」；
3. **跑偏**：输出变成 800 字理财课，或者开始劝人「要爱自己」。

这三件事在答辩现场都是致命的。所以这条链的目标不是「写得更好」，而是
**把模型的自由度压到只剩语气**。

## 1. 第一轮 Prompt（原文）

```
现在接 AI 卦辞。我的想法是：账已经在本地算完了，模型只负责讲，不负责算。

第一版就这样：
- 把账单摘要（收入、支出、结余率、六爻、人格、燃尽、处方）序列化成 JSON，
  作为 user message；
- system 里写清楚「你是卦师，根据这份卦案讲解」；
- 用 OpenAI 兼容的 /chat/completions，stream: true，前端逐字渲染；
- 没有 API Key 的时候不要报错，直接退回本地的文案。

你先给我 prompts.ts、payload.ts、api route，别做 UI。
```

### AI 首版产出

- `payload.ts`：`OraclePayload` 信封（v1）
- `prompts.ts`：`ORACLE_SYSTEM_PROMPT` / `CHAT_SYSTEM_PROMPT`
- `app/api/oracle/route.ts`：SSE 转发 + 无 Key 降级

第一版能跑，但把同一份卦案连续请求三次，出现了三类偏差。

## 2. 我发现的偏差（用同一份学生账单连问 3 次）

| # | 现象 | 根因 | 对策 |
| --- | --- | --- | --- |
| 1 | 第一次说「支出 ¥1,367.90」，第二次说「不到 1,400」，第三次说「约 1,370」 | 信封里给的是数字，模型自己做了一次「约等于」 | 信封里的数字**全部预格式化成字符串**（`"¥1,367.90"`），提示词要求「只能原样引用」 |
| 2 | 出现「你的订阅比上月多了 2 个」 | 信封里没有上月数据，模型补了不存在的对比 | 明确写入「卦案里没有的，一律不写」，并删掉任何可能诱导对比的字段 |
| 3 | 输出 600+ 字，第三段开始讲通用理财建议 | 没有结构约束，模型自由发挥 | 固定四段结构 + 字数区间（260–420 字）+ 禁用清单 |
| 4 | 有一次把「情绪结算员」写成「你有点冲动消费的人格缺陷」 | 人格词被当成评价 | 加铁律「不评判人格缺陷，只点评账单结构」 |
| 5 | 没有 Key 时页面直接显示「请配置 API Key」 | 降级路径只做了报错，没做内容 | 增加**本地卦辞**作为对照组与兜底 |

## 3. 第二轮引导 Prompt（原文）

```
有三个问题要一起解决：数字被模型改写、内容跑偏、没 Key 时页面没内容。

请按这个思路改：

1. 信封里所有数字都变成「已经格式化好的字符串」，例如 "¥1,367.90"、"24.3%"、"第 23 天"。
   提示词里明确：「只能引用这些字符串，禁止换算、禁止相加、禁止四舍五入」。
2. 系统提示固定四段结构：①一句断语（≤20 字）②最疼的一爻（引用该爻数值）
   ③燃尽日与结构性问题 ④今天就能做的一个动作 + 月省金额。总长 260–420 字。
3. 加禁用清单：不做投资/借贷/法律/医疗建议；不羞辱人格；不用 Markdown 标题与列表；
   不写卦案里没有的商户与月份对比。
4. 再写一份 localNarrative(payload)：完全本地的四段卦辞，不经过任何模型。
   它的作用有两个：没 Key 时的完整体验，以及 AI 输出的对照组。
5. 路由行为：无 Key 返回 { mode: "local" }；上游非 2xx / 超时也返回 200 + local，
   前端按 mode 决定渲染哪一份，绝不白屏、绝不弹红框。

验收我会做三件事：
- 同一份卦案连问 3 次，所有金额必须与本地卦辞一字不差；
- 把 AI 输出里出现的每个数字，逐个到信封里能找到，找不到就算失败；
- 拔掉 Key，页面仍然有完整四段卦辞。
```

### AI 修正后的落点

- `payload.ts`：`toPayload()` 里所有金额走 `formatCents()`、所有比例走 `toFixed(1)%`，
  连燃尽日也格式化成 `"第 23 天"` 或 `"不会见底"`；
- `prompts.ts`：

```
【铁律】
1. 账已经由确定性引擎算完。你只解释，不计算、不换算、不新增任何数字。
2. 只能引用卦案里出现的金额、百分比、日期、商户名；卦案里没有的，一律不写。
3. 不提供投资、借贷、贷款、法律、医疗建议；不预测收入变化。
4. 不评判人格缺陷，只点评账单结构；可以犀利，不可以羞辱。
5. 用中文，口语，短句，克制，有画面感。不要 Markdown 标题、不要列表符号、不要表情。
```

- `narrative.ts`：`localNarrative()` 四段式，且刻意与信封字段一一对应；
- `api/oracle/route.ts`：`readAiConfig()` 缺 Key 直接 `Response.json({ mode: "local" })`；
  上游异常 `catch` 后同样返回 200 + local + reason；
- `streamClient.ts`：按 `content-type` 分流，SSE 按行解析 `data:`，坏事件跳过不整体失败；
- `api/chat/route.ts`：追问复用同一信封，历史只带最近 4 轮，问题上限 300 字。

## 4. 人工验收（无 Key / 有 Key 两条路径都跑）

| 检查项 | 方法 | 结果 |
| --- | --- | --- |
| 无 Key 时有完整卦辞 | 清空 `AI_API_KEY` 重启，打开卦盘 | 显示「本地卦辞」，四段齐全，角落标注原因 |
| 有 Key 时流式输出 | 填入方舟 Key 与 `ep-` 接入点 | 「AI 卦辞」逐字出现，光标跟随 |
| 数字一致性 | 把 AI 输出复制出来，逐个数字比对信封 | 全部命中（金额、占比、第 N 天、处方金额） |
| 上游失败降级 | 故意把 `AI_BASE_URL` 改成不可达地址 | 页面仍显示完整卦辞，角落标注「上游连接失败」 |
| 追问不跑偏 | 问「哪一爻最该先补？」 | 回答限定在卦案与处方内，140 字以内 |

> 备注：表格后两行需要在有 Key 的环境执行；仓库不包含任何 Key，
> 评审可自行填入自己的 Key，或在无 Key 状态下验证降级路径。

## 6. 复盘：这条链教会模型什么

1. **把「计算」从模型手里拿走**：一旦允许它换算，就允许它出错；让它只做措辞，错误率下降一个量级。
2. **格式即约束**：数字预格式化成字符串，比写十句「不要编造」都有效，因为「引用」比「计算」容易。
3. **结构比字数更能防跑偏**：四段结构让输出有边界，模型很难在 420 字里塞进理财课。
4. **降级路径要产出内容，而不是产出错误**：无 Key / 上游挂了都返回可读的四段卦辞，只是标明来源，
   这才叫「工程上的可用」，而不是「配置齐全才可用」。
